ChangeCouncil uses the system codex binary, not the SDK's bundled one

council/summon.ts · getCodexExecutablePath()

The first live run failed: "The 'gpt-5.5' model requires a newer version of Codex." Root cause: @openai/codex-sdk@0.79.0 ships a bundled codex 0.79.0 binary, which rejects gpt-5.5; the system has codex 0.133.0, which accepts it. The resolver now prefers a system codex on PATH over the bundled binary (priority: config > CODEX_PATH env > system PATH > bundled).

Decision not in spec: chose this over upgrading the SDK dependency (0.79 → 0.133). I verified by live probe that SDK 0.79 drives the 0.133 binary fine (returned COUNCIL_OK), so no dependency bump was needed — lower risk, no API churn. Tradeoff: relies on a system codex being installed; if none is found it falls back to the (older) bundled binary, which will fail on newer models. Document codex as a runtime prereq.

ChangeDeliberation transcripts now save to project-local deliberations/

state/path.ts, modelCouncil.ts · user-requested

Moved the save target from ~/.agents-council/runs/ to <project>/deliberations/. New resolveDeliberationsDir() anchors the path to the source file via import.meta.url (not process.cwd()), with env override AGENTS_COUNCIL_DELIBERATIONS_DIR.

Why anchored to source, not cwd: bun run cli can be invoked from a subdirectory; cwd-relative would scatter the folder. Decision not in spec: added deliberations/ to .gitignore and excluded it from biome — transcripts are generated artifacts and one run's JSON exceeded biome's 1 MiB limit. Tradeoff: transcripts are not version-controlled; remove the gitignore line if you want them tracked. The folder is created lazily on the first successful save, so it won't exist until a run completes.

ChangeOpenRouter calls hardened (the "Kimi empty response" bug)

modelCouncil.ts · askOpenRouter()

Kimi K2.6 is reasoning-capable; on some calls it returns the answer in a non-content field, or OpenRouter returns a transient 200 with an empty body. The parser now: reads raw text first (so empty/non-JSON bodies stay diagnosable), extracts from content (string), content (array of parts), or reasoning; retries up to 3× on empty/429/5xx with backoff; and emits a diagnostic error (finish_reason + provider error + raw snippet) on true failure.

Decision not in spec: did not add max_tokens headroom even though it could help reasoning models — root CLAUDE.md Hard Rule 1 forbids changing token-limit params without asking, and the failure was an empty body, not a length cutoff. Flag if you want a configurable max_tokens.

Heads-upMembers only receive prompt text — they cannot read file paths

architecture limitation

The autonomous loop passes only the prompt string to each member. OpenRouter members and Opus (tools denied) cannot open files referenced by path; only the Codex member could, but it runs read-only/no-network. To ask about a file, inline its contents into the prompt (which is what the κ-CMA run did — its question embedded the full v1 process text).

Possible follow-up: a --file flag that auto-inlines referenced files for all members (offered, not yet built).

ChangeConvergence: trajectory metrics, near-convergence threshold, higher round cap

modelCouncil.ts + tests · user-requested ("implement them all")

Diagnosing why a 4-round run showed consensus: blocked revealed the convergence test was binary (a round counted as converged only if its shared candidate was byte-identical to the prior round's). Verbose models never reach that, so the run hit the cap mid-convergence and defaulted to "blocked by all" — even though members were steadily agreeing. Three fixes:

  • Trajectory metrics on every ModelCouncilRound: similarityToPrevious and memberAgreement (token-set Jaccard, 0..1), surfaced in a new Markdown Convergence section + trend line.
  • Near-convergence threshold DEFAULT_CONVERGENCE_SIMILARITY_THRESHOLD = 0.95: a round converges if the shared candidate is byte-identical or ≥0.95 token-similar to the previous round, so it proceeds to ratification instead of looping forever.
  • Round cap raised 4 → 6 (DEFAULT_MAX_CONSENSUS_ROUNDS), now also overridable via AGENTS_COUNCIL_MAX_ROUNDS.
DecisionChoice & rationale
Which signal gates convergencesimilarityToPrevious (shared-candidate stability), matching the stated "shared similarity" intent. memberAgreement is recorded for visibility but is not a gate, to keep the stop condition predictable.
Similarity metricToken-set Jaccard — cheap and dependency-free. Tradeoff: lexical, not semantic; good for a trend, not a precise agreement score.
Round cap = 6The blocked run trended 0.648→0.918 shared-similarity; ~1–2 more rounds would have crossed 0.95. Tradeoff: more rounds = more cost (each round = 5 model calls); the 0.95 early-stop offsets this by exiting as soon as it stabilizes.

Robustness: the Markdown formatter tolerates pre-feature transcripts (renders — when metrics are absent). A throwaway backfill script recomputed metrics for the existing blocked run, whose Markdown now shows agreement rising 0.232 → 0.710 across its 4 rounds.

DecisionGPT-5.5 Pro: investigated, kept on subscription gpt-5.5

no code change · user decision

Asked whether the council could use gpt-5.5-pro ("available on the web"). Findings:

  • Via Codex (ChatGPT subscription): blocked by OpenAI — the backend returns 400 invalid_request_error: "The 'gpt-5.5-pro' model is not supported when using Codex with a ChatGPT account." This is a tier restriction, not a version issue (tested on codex 0.133.0). The web ChatGPT app and the Codex programmatic surface are different access tiers.
  • Via OpenRouter (API, pay-per-token): available as openai/gpt-5.5-pro, but premium-priced at ~$30/M input / $180/M output — 6× plain gpt-5.5 — and it shifts the ChatGPT seat off the flat subscription onto metered OpenRouter billing. The council runs multiple rounds with growing context, so cost compounds.

Decision: keep gpt-5.5 @ xhigh via the Codex subscription; do not add Pro. To revisit: switching the ChatGPT seat to OpenRouter would be a code change — the model is env-overridable (AGENTS_COUNCIL_CHATGPT_MODEL) but the provider (codex vs openrouter) is hard-coded per member in buildDefaultMembers().

Heads-upToken-cost profile — the council is NOT token-efficient (not yet optimized)

analysis · OpenRouter members (Kimi, DeepSeek, Gemini)

Estimated from the existing 4-round run (ratification did not fire — it ended blocked):

MetricValue
Total OpenRouter input~834,000 tokens
Total OpenRouter output~74,000 tokens
Input : output~11 : 1
Input amplification~16× vs. sending the prompt once per member
Rough blended cost~$0.50–1.50 (this run)

Why so high: each deliberation call re-sends the original prompt + all initial proposals + the previous round's full member essays + the candidate, fresh every round, to every member, with no caching. The user-inlined v1.md (~18K tokens) alone was re-sent on all 12 calls (~215K tokens). formatCouncilResponses embeds full .content (reasoning included), not just the candidate draft. Ratification (formatConsensusRounds) re-sends every round's full proposals to every member — a latent cost bomb that only stayed dormant here because the run ended blocked. Cost scales ~quadratically in members×rounds, so the new 6-round cap + ratification firing would push this ~2–3×.

Optimization backlog, high→low leverage: (1) prompt-cache the static prefix — DONE; (2) send candidate drafts not full essays in peer context — deferred (largest deterministic win but members see less peer reasoning); (3) drop initial proposals from rounds ≥2 — DONE; (4) trim ratification to final candidate + last round — DONE; (5) cap output / lower reasoning effort — deferred (needs sign-off, Hard Rule 1); (6) skip members whose draft already matches the candidate — deferred (changes deliberation behavior).

ChangeToken-efficiency pass: caching + drop-redundant-context + ratification trim (#1, #3, #4)

modelCouncil.ts + tests · user-approved bundle
  • #1 Prompt caching. ChatMessage.content now accepts cache-marked content parts (ChatContentPart). The deliberation user message splits into a cache-marked static prefix (Original request:\n{prompt}) + a dynamic remainder. To make that prefix byte-stable across rounds, the round number was moved out of the system message into the dynamic body, so the [system + prefix] cache key is identical every round for a given member. Codex/Claude paths flatten parts to text via flattenMessageContent().
  • #3 Drop initial proposals from rounds ≥2. Initial independent proposals are only included in round 1; later rounds rely on the candidate consensus + latest peer proposals.
  • #4 Trim ratification. Replaced formatConsensusRounds() (re-sent every round's full proposals to every member — O(rounds×members)) with the final round's positions only. The dead formatConsensusRounds helper was removed; buildRatificationMessages lost its now-unused responses parameter (signature change — caller + test updated).

Measured (replaying the existing 4-round run, 3 OpenRouter members): deliberation input 780K → 608K raw (−22%), or ~462K billed (−41%) where the provider honors caching (~161K of prompt prefix served from cache on rounds ≥2); ratification, when it fires, 486K → 212K (−56%). Tradeoffs / caveats: caching benefit is provider-dependent (DeepSeek/Gemini likely honor it; Kimi/Moonshot uncertain) — the deterministic floor is the −22%/−56% raw reductions. Ratifiers now see only the latest peer positions, not the full deliberation history (they participated in every round, so this is acceptable). Round ≥2 members no longer re-read the round-1 independent proposals. Output tokens are untouched (no max_tokens change — Hard Rule 1).
