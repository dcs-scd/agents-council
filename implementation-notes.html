Session 2026-06-08 — WU-A1 executed (remove Bearer from curl argv)

Decision Auth header routed through a 0600 curl --config temp file, not stdin -K -

2026-06-08 · src/core/services/modelCouncil.ts → fetchTextWithTimeout

The WU offered two non-argv channels for the Authorization header: stdin (curl -K - / --config -) or a 0600 temp file. stdin is already consumed by the POST body (--data-binary @-), so -K - would collide with the body. Chose a per-request 0600 temp config file (header = "Key: Value" lines), passed via --config <path>, and rm'd after proc.exited (curl has read it by then). All headers — not just Authorization — move into the file, so no header value remains as an argv element at all.

Why: minimal-diff, preserves the body-on-stdin contract, and removes the secret from ps//proc/<pid>/cmdline entirely (INV-1).

Heads-upRoot cause of outcome=blocked when ratifiers actually agree

modelCouncil.ts · diagnosed from the 2026-06-01 Tier-4 transcript

Two compounding defects, both in the serialization/ratification protocol (the deliberation succeeded):

  • Unratifiable candidate. buildCandidateConsensus only emitted a single clean draft when the members' CANDIDATE_CONSENSUS: blocks were normalized-identical (size===1). Net: ratify was handed a document that announces its own non-unification, and each member's "Path to ACCEPT" was discarded → outcome=blocked with both ratifiers agreeing on the final artifact.

Tell: the transcript's two final votes both led with CONSENSUS: BLOCK but each ended in a concrete "make exactly these edits and I ACCEPT" — the protocol had no way to act on that.

ChangeBounded one-shot consensus-repair cycle
