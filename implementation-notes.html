Decision Fenced-payload extraction added — the wrappers' whole-content JSON.parse could never see a D1 reply

2026-07-12 · extractStructuredPayload in src/core/services/modelCouncil.ts

The spec said the wrappers "already fall back to legacy internally — verify, don't assume." Verified: they do, but they JSON.parse the whole reply. Since D1 keeps the legacy markers REQUIRED and makes the payload additive, every compliant reply is markers + fence — never valid JSON as a whole — so the structured parse would have failed 100% of the time and the <5% promotion criterion could never be met. Added a single extraction helper: the last ```json fence wins; a reply that IS a bare JSON object (the pre-D1 shape used by existing tests and JSON-only members) is accepted as-is; otherwise the payload is "absent". The same extraction now feeds the wrappers, extractStructuredClaims (trace), and evaluateRatificationPreconditions (D4).

Why it matters: without this, D2's wiring would be dead code on real traffic and D3's stats would record only failures.

Decision Synthesis/fold replies stay on the legacy candidate parser

2026-07-12 · runModelCouncil repair + fold call sites

D2 names three wrappers; each got exactly one live call site: candidate → askDeliberation, vote → ratifyCandidate, signal → isConverged (via a pre-parsed optional argument, keeping isConverged sync and its exported contract intact). The synthesis and fold call sites still use legacy parseCandidateConsensus: D1 does not add the payload instruction to synthesis prompts, so a structured parse there buys nothing — and the wrapper's markerless fallback (raw.trim()) would have silently changed flag-on repair semantics (a markerless synthesis reply currently aborts the repair; the wrapper would have promoted the whole reply to a candidate).

Why it matters: narrowest interpretation that satisfies the spec without disturbing Lane A/B repair/fold behavior.

Change D3 stats: ok / fail / absent per member+phase, on the result and in the trace

2026-07-12 · StructuredParseStat, result.structuredParseStats, trace parseStats[]

The wrappers take an optional outcome callback (additive — no existing caller breaks); the run state accrues aggregate counts per member+phase (deliberation, ratification). "absent" (member ignored the instruction) is tracked separately from "fail" (payload present but invalid JSON / schema), so the promotion rate is fail / (ok + fail). The result field appears only when something was recorded — flag-off result JSON is unchanged. Trace keeps schema_version v1 (additive field; council_to_brief.py reads only its required top keys); parseStats is sorted member-then-phase since phase completion order is nondeterministic under Promise.allSettled.

Why it matters: the operator computes the <5% criterion offline from saved traces alone, which is the whole point of stage v2.

Tradeoff One deliberation reply is signal-parsed twice under the flag (stats counted once)

2026-07-12 · askDeliberation vs structuredRoundSignals

The candidate parse (askDeliberation) and the convergence-signal parse (isConverged input) both validate the same payload against DeliberationResponseSchema. The signal path deliberately does not record stats — recording both would double-count each deliberation turn. Cost is one extra JSON.parse+zod per member per round, flag-on only; threading the parsed object across the two seams would have coupled the exported wrapper contracts.

Why it matters: keeps the seams independent and the accrual honest at trivial runtime cost.

Heads-up Flag-on candidate precedence changed: a schema-valid payload now beats the legacy marker

2026-07-12 · askDeliberation under AGENTS_COUNCIL_STRUCTURED=1

Pre-D2 flag-on behavior parsed the marker first and only used the raw reply when markerless. Now the payload's candidateConsensus wins when it validates, falling back to marker, then raw reply. If a member emits a marker and payload that disagree, the payload is authoritative. Also: the global getParseFailStats() counter in schemas.ts still ticks (read only by its own unit tests); the docs' pre-existing "JSON mode is requested where the provider supports it" line is aspirational — stage v2 requests the payload via prompt, not provider JSON mode. Left as-is (pre-existing text, outside D3's named doc edits).

Why it matters: reviewers diffing flag-on transcripts pre/post Lane D should expect candidate text to come from the payload, not the marker tail.

Change New MCP tool wait_for_session_data — server-side block instead of agent-side poll

2026-06-23 · src/interfaces/mcp/{server.ts, sessionDataWait.ts, sessionDataWait.test.ts, dtos/types.ts} + README

Heads-upRoot cause of outcome=blocked when ratifiers actually agree

modelCouncil.ts · diagnosed from the 2026-06-01 Tier-4 transcript

Two compounding defects, both in the serialization/ratification protocol (the deliberation succeeded):

  • Unratifiable candidate. buildCandidateConsensus only emitted a single clean draft when the members' CANDIDATE_CONSENSUS: blocks were normalized-identical (size===1). ChangeBounded one-shot consensus-repair cycle

design choice

TradeoffDropped Anthropic-style cache_control on the Gemini path

The OpenRouter path marks a stable prompt prefix with cache_control: { type: "ephemeral" } so providers that honor it serve repeated rounds from cache. Tradeoff: per-deliberation cost on the Gemini member will not benefit from prefix caching; for short multi-round runs the savings would have been small, and the Gemini CLI's pricing/quota is governed by Google's tier anyway.
