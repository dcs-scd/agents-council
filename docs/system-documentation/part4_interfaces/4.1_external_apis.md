# 4.1 External API Documentation

> **Last Updated:** 2026-05-22
> **Related:** [4.4 Integration Catalog](4.4_integrations.md) · [2.3 Data Flow](../part2_architecture/2.3_data_flow.md) · [6.2 Auth](../part6_security/6.2_auth.md)

---

`agents-council` consumes external services in two areas only: **summoning** agents (via local CLIs/SDKs) and the **Model Council** (via OpenRouter + Codex auth). The core council flow consumes nothing external.

## Summary of External Dependencies

| Service / API | Used by | Transport | Auth |
|---------------|---------|-----------|------|
| Claude Agent SDK → `claude` CLI | Summon Claude, model discovery | In-process SDK spawning the `claude` binary | Reused `claude` auth |
| OpenAI Codex SDK → `codex` CLI | Summon Codex, ChatGPT council member | Codex SDK thread + `app-server` JSON-RPC | Reused `codex login` |
| OpenRouter Chat Completions | Kimi & DeepSeek council members | HTTPS `fetch` | `OPENROUTER_API_KEY` |

## Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`)

Used by `summon.ts` for two purposes.

### Summoning a Claude agent
`query()` runs a fresh Claude agent with the council tools injected as an in-process MCP server:

```typescript
const response = query({
  prompt: createPromptMessages(prompt),
  options: {
    pathToClaudeCodeExecutable: claudeCodePath,   // resolved absolute path
    mcpServers: { council: councilServer },        // join/get/send tools
    model: model ?? undefined,
    permissionMode: "default",
    settingSources: ["user"],                       // honor user permission settings
    canUseTool: async (toolName, input) =>
      isSummonToolAllowed(toolName)
        ? { behavior: "allow", updatedInput: input }
        : { behavior: "deny", message: "...", interrupt: false },
  },
});
```

- **Tool policy.** `canUseTool` allows only `mcp__council__*` tools plus `Read`/`Glob`/`Grep`; everything else is denied. This is the read-only summon sandbox ([ADR-07](../part2_architecture/2.4_adrs.md)).
- **Result handling.** The stream is consumed until a `result` message; `resolveSummonResultError` distinguishes `is_error`, non-success subtypes, and empty results into precise error messages.

### Model discovery
`fetchClaudeSupportedModels()` runs a `query` with `maxTurns: 0` and calls `response.supportedModels()` (8 s timeout), mapping each to a `SummonModelInfo`. The query is interrupted (fire-and-forget) afterward.

## OpenAI Codex SDK (`@openai/codex-sdk`)

Used in three places.

### Summoning a Codex agent
```typescript
const codex = codexPath ? new Codex({ codexPathOverride: codexPath }) : new Codex();
const thread = codex.startThread({
  model: model ?? undefined,
  modelReasoningEffort: <minimal|low|medium|high|xhigh>,
  sandboxMode: "read-only",
  workingDirectory: process.cwd(),
  skipGitRepoCheck: true,
  approvalPolicy: "never",
  networkAccessEnabled: false,
  webSearchEnabled: false,
});
const turn = await thread.run(prompt);   // → turn.finalResponse
```

The agent runs fully read-only with networking and web search disabled. Its `finalResponse` becomes a feedback row.

### ChatGPT model-council member
`askCodex()` in `modelCouncil.ts` uses the same read-only thread mechanism to run the ChatGPT member (`gpt-5.5-pro` by default) through the local Codex/OpenAI subscription auth — no API key required beyond `codex login`.

### Codex model discovery (`app-server` JSON-RPC)
`fetchCodexModelsViaAppServer()` spawns `codex app-server` and speaks JSON-RPC over stdio:

```text
→ initialize { clientInfo }
→ (notify) initialized
→ model/list {}
← { data: [ { id|model|value, displayName, description, supportedReasoningEfforts, ... } ] }
```

Each result is normalized to a `SummonModelInfo`. The whole exchange is bounded by the 8 s timeout, and the subprocess is killed afterward.

## OpenRouter Chat Completions

`askOpenRouter()` in `modelCouncil.ts` calls OpenRouter for the Kimi and DeepSeek members.

**Endpoint:** `POST https://openrouter.ai/api/v1/chat/completions`

**Headers:**
| Header | Value |
|--------|-------|
| `Authorization` | `Bearer ${OPENROUTER_API_KEY}` |
| `Content-Type` | `application/json` |
| `X-Title` | `Agents Council` |
| `HTTP-Referer` | `${OPENROUTER_HTTP_REFERER}` (only if set) |

**Body:** `{ model, messages }` where `messages` is the standard `{role, content}[]` chat format.

**Response handling:** reads `choices[0].message.content`; a non-OK response surfaces `error.message`, and an empty content throws `"<member> returned an empty OpenRouter response."`.

**Default models** (override via env):

| Member | Default model | Env override |
|--------|---------------|--------------|
| Kimi 2.6 | `moonshotai/kimi-k2.6` | `AGENTS_COUNCIL_KIMI_MODEL` |
| DeepSeek V4 Pro | `deepseek/deepseek-v4-pro` | `AGENTS_COUNCIL_DEEPSEEK_MODEL` |
| ChatGPT 5.5 Pro | `gpt-5.5-pro` | `AGENTS_COUNCIL_CHATGPT_MODEL` |

## Error & Resilience Behavior

| Failure | Behavior |
|---------|----------|
| `OPENROUTER_API_KEY` missing | `validateCouncilConfig` throws before any call |
| OpenRouter non-OK / empty | Throws a member-named error; the whole council run rejects |
| Codex/Claude binary not found | Resolution falls back to the bare command name; SDK surfaces the error |
| Model discovery timeout (8 s) | Returns empty list; falls back to cache / config-file default |
| Summoned agent returns nothing | Throws `"<agent> did not submit/return a response."` |

> **Cost note.** A single `run_model_council` makes up to `members × (1 proposal + ≤4 deliberation + 1 ratification)` model calls — i.e. up to ~18 calls across three models. Treat it as a deliberate, billable operation. See [5.3 Environments](../part5_infrastructure/5.3_environments.md).
