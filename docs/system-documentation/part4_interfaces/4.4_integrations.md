A complete catalog of the libraries, SDKs, runtimes, and tools `agents-council` depends on, with the role each plays. Versions are from `package.json` at v0.4.0.

## Runtime & Build Dependencies

| Package | Version | Role |
|---------|---------|------|
| **Bun** | runtime | Execution engine; `Bun.serve`, `Bun.spawn`, `Bun.file`, `Bun.TOML`, standalone-binary compile target |
| `electrobun` | 1.13.1 | Cross-platform desktop runtime (bun process + native webview), RPC bridge, packaging |
| `@modelcontextprotocol/sdk` | 1.25.1 | MCP server, stdio transport, tool registration, `CallToolResult` types |
| `@anthropic-ai/claude-agent-sdk` | 0.1.76 | Summon Claude: `query()`, in-process MCP `tool()`/`createSdkMcpServer()`, `supportedModels()` |
| `@openai/codex-sdk` | 0.79.0 | Summon Codex + ChatGPT council member: `Codex`, read-only threads, reasoning effort |
| `commander` | 14.0.2 | CLI argument parsing (`mcp`, `chat`, `solve`) |
| `zod` | 4.2.1 | MCP tool input schemas + summon tool input validation |
| `react` / `react-dom` | 19.2.3 | Council Hall renderer |
| `@uiw/react-markdown-preview` | 5.1.5 | Markdown rendering of requests/feedback in the UI |

## External Services

| Service | When used | Auth | Required? |
|---------|-----------|------|-----------|
| `claude` CLI (Claude Code) | Summon Claude, Claude model discovery | One-time `claude` auth | Only for Summon Claude |
| `codex` CLI (OpenAI Codex) | Summon Codex, ChatGPT council member, Codex model discovery | `codex login` | Only for Summon Codex / Model Council |
| OpenRouter | Kimi + DeepSeek council members | `OPENROUTER_API_KEY` | Only for Model Council |

The **core council flow has no external service dependency** — it works with nothing but Bun and the local filesystem.

## Distribution Integrations

| Channel | Detail |
|---------|--------|
| **npm** | Main package `agents-council` + five per-platform optional dependencies (see below) |
| **GitHub Releases** | Electrobun desktop artifacts (`.dmg`, `.tar.zst`, `update.json`, `Setup.*`) per platform |
| **GitHub Actions** | CI (`ci.yml`) + release (`release.yml`) |

### Per-platform npm packages
```
agents-council                   (main wrapper, optionalDependencies → the 5 below)
agents-council-darwin-arm64
agents-council-darwin-x64
agents-council-linux-arm64
agents-council-linux-x64
```

Each platform package ships the `council` CLI binary plus the Electrobun desktop artifacts for that platform.

## MCP Client Integrations

The council registers into any MCP client. Documented setups:

| Client | Command |
|--------|---------|
| Claude Code | `claude mcp add council npx agents-council@latest mcp` (or `-s user -- npx agents-council@latest mcp -n Opus`) |
| Gemini CLI | `gemini mcp add council npx agents-council@latest mcp` |
| Codex | `codex mcp add council npx agents-council@latest mcp` |
| amp | `amp mcp add council npx agents-council@latest mcp` |
| Generic | `{ "mcpServers": { "council": { "command": "npx", "args": ["agents-council@latest","mcp"] } } }` |

## Project-Management Integration

The repo uses **Backlog.md** (an MCP-based task manager) for its own development workflow — `backlog/` holds milestones and tasks, and `CLAUDE.md`/`AGENTS.md` instruct contributing agents to read `backlog://workflow/overview` before creating tasks. Two vendored skills (`backlog-technical-project-manager`, `context-hunter`) are pinned in `skills-lock.json`. This is a *development* integration, not a runtime one.

## Vendored Documentation

`docs/` mirrors upstream docs for offline reference: Bun, MCP spec (2025-11-25), Electrobun, Claude Agent SDK, and Codex SDK. These are reference material for contributors, not shipped with the package (`package.json` `files` ships only `scripts/*.cjs`, `README.md`, `LICENSE`).
