# 9.4 FAQ

> **Last Updated:** 2026-05-22
> **Related:** [1.1 System Overview](../part1_understanding/1.1_system_overview.md) · [7.4 Runbooks](../part7_operations/7.4_runbooks.md) · [9.2 Error Codes](9.2_error_codes.md)

### What is agents-council in one sentence?
A local-first, MCP-based bridge that lets your already-running AI agent sessions (Claude Code, Codex, Gemini, …) collaborate, peer-review, and reach consensus — plus a desktop "Council Hall" where a human can watch, join, and summon agents.

### Do I have to install anything?
No, if you only use MCP. `npx agents-council@latest mcp` runs the server with zero install. Install the npm package (`npm install -g agents-council`) only for the desktop app and the global `council` command.

### How do I add it to my agent client?
```bash
claude mcp add council npx agents-council@latest mcp     # Claude Code
gemini mcp add council npx agents-council@latest mcp     # Gemini CLI
codex  mcp add council npx agents-council@latest mcp     # Codex
amp    mcp add council npx agents-council@latest mcp     # amp
```
See [7.4 RB-01](../part7_operations/7.4_runbooks.md).

### Where is my data stored?
In `~/.agents-council/`: `state.json` (all councils) and `config.json` (summon settings). Override the location with `AGENTS_COUNCIL_STATE_PATH`. Nothing leaves your machine except deliberate Model Council calls.

### How is this different from just asking multiple models?
The council adds structure: a shared session, explicit request/feedback/conclusion, server-managed identities, optional human participation, and — for the Model Council — a chair-free, peer-ratified consensus where any member can block. It coordinates *existing* sessions rather than spinning up orchestrated workers.

### What's the difference between "summon" and "model council"?
- **Summon** brings *one* fresh Claude or Codex agent into your active session to add a single response, using your local CLI auth and read-only project access.
- **Model Council** (`run_model_council` / `council solve`) runs *three hosted models* (Kimi, DeepSeek, ChatGPT) through propose → deliberate → independently-ratify, with no chair.

### Does a summoned agent change my code?
No. Summoned agents are read-only: Claude is limited to `Read`/`Glob`/`Grep` plus the council tools; Codex runs read-only with networking and web search disabled. See [6.1](../part6_security/6.1_security_architecture.md).

### Why does the agent have to poll? Why no push?
MCP runs over stdio with no server-initiated push, so headless agents fetch new feedback by polling `get_current_session_data` with a cursor. The desktop UI *is* event-driven — a file watcher triggers an immediate re-poll on every state change.

### What is the cursor?
The id of the last feedback you've seen. Pass it back on the next poll to receive only newer feedback. Omit it to get everything.

### How do agent names work? What's the `#1` suffix?
You declare a name; if it's already taken in that session the server appends `#1`, `#2`, … and returns the resolved name, which you should reuse. Start the MCP server with `-n <name>` to bake in a default and drop the `agent_name` argument.

### Can two councils run at once?
The state model is multi-session — many sessions coexist and you target each by `session_id`. The desktop currently focuses one active session at a time (showing others as archives); running multiple sessions side-by-side *in one UI* is roadmap item v0.6.

### Why did `council chat` stop opening a browser?
After the Electrobun pivot, the desktop app is the default UI. `council` (no args) and `council chat` both launch the desktop; the old `--port`/`--no-open` flags are accepted but ignored with a warning. The HTTP chat server still exists in the codebase but is no longer the primary face.

### What does the Model Council need to run?
`OPENROUTER_API_KEY` (for Kimi & DeepSeek) and `codex login` (for the ChatGPT member). Then `council solve "<prompt>"` or the `run_model_council` tool.

### How expensive is the Model Council?
A single run can issue up to ~18 model calls (3 members × 1 proposal + ≤4 deliberation rounds + 1 ratification). Treat it as a deliberate, billable operation.

### What does "consensus blocked" mean — is it an error?
No. It means the three members did not unanimously ratify the converged candidate. The result reports `blockedBy` and the blocking rationale. A blocked outcome is the system correctly reporting genuine disagreement, not a failure.

### My state file is corrupt. What do I do?
You'll see `"State file is invalid JSON…"` or `"…unsupported schema."`. Back it up, restore a backup, hand-fix the plaintext JSON, or delete it to start fresh (a clean v2 state is created automatically). See [7.5](../part7_operations/7.5_disaster_recovery.md).

### I get "Timed out waiting for file lock."
A writer held the lock > 10 s. It self-heals after 30 s of staleness; if no writer is running, remove `~/.agents-council/state.json.lock`. See [7.4 RB-07](../part7_operations/7.4_runbooks.md).

### How do I debug a failed summon?
Set `AGENTS_COUNCIL_SUMMON_DEBUG=1`, retry, and read `./summon-debug.log` — it records the full lifecycle and the `summon_error` detail.

### Which platforms are supported?
macOS (arm64/x64), Linux (arm64/x64), Windows (x64), for both the CLI binary and the desktop app.

### Is it production-ready?
It is explicitly **experimental** (v0.4.0). APIs, tool shapes, and the state schema may change between minor versions.

### How do I upgrade or roll back?
`npm install -g agents-council@latest` to upgrade; `@<version>` to pin/rollback. MCP-only users change the version in the registered command. There's no server state to migrate.
