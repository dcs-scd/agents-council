# 8.3 Testing Strategy & Guide

> **Last Updated:** 2026-05-22
> **Related:** [8.1 Local Setup](8.1_local_setup.md) · [8.4 CI/CD](8.4_cicd.md) · [3.3 Access Patterns](../part3_data/3.3_access_patterns.md)

---

Tests run on **`bun test`** (Bun's native runner; no separate `test` script — Bun auto-discovers `*.test.ts`). Coverage is focused on the layers where correctness matters most: the domain service, the persistence/migration store, the DTO mapper, the bridge actions, and the Model Council prompt protocol.

## Test Suites

| File | Layer | Covers |
|------|-------|--------|
| `src/core/services/council/index.test.ts` | Domain | Multi-session lifecycle, create/list/retrieve, deterministic ordering, status transitions |
| `src/core/state/fileStateStore.test.ts` | Persistence | JSON parse/error handling, v1→v2 migration, locking, atomic writes, no leftover `.lock` |
| `src/interfaces/mcp/mapper.test.ts` | Adapter | DTO ⇄ domain mapping; session-scoped projection for get/send |
| `src/interfaces/chat/bridge/actions.test.ts` | Adapter | Full start→join→send→get→close flow; multi-session isolation; watcher notifications |
| `src/core/services/modelCouncil.test.ts` | Consensus | Proposal / deliberation / ratification prompt construction and protocol |

## Running Tests

```bash
bun test                                   # all suites
bun test src/core/state                    # a directory
bun test src/core/services/council/index.test.ts   # a single file
bun test --watch                           # watch mode
```

## Conventions

- **Co-located.** Each `*.test.ts` sits beside the module it tests.
- **Bun test API.** `import { describe, test, expect, afterEach } from "bun:test"`.
- **Isolated state.** Store/service/action tests use a **temporary state path** (a `withTempStatePath`-style helper) so they never touch the real `~/.agents-council/`. Temp dirs are cleaned in `afterEach`.
- **No leftover locks.** Store tests assert that `.lock` files are removed after operations.
- **Pure where possible.** The Model Council tests exercise the *prompt builders* (`buildProposalMessages`, `buildDeliberationMessages`, `buildRatificationMessages`) directly, without network calls.

## What Each Suite Asserts (highlights)

### Domain (`council/index.test.ts`)
- Starting a council creates an active session + open request + participant and sets it active.
- Listing sorts active-first then by recency (`sortSessionsForListing`).
- Closing a session seals the conclusion, closes the request, and re-resolves the active session.
- Agent-name collisions resolve to `#N` while existing names are reused.

### Persistence (`fileStateStore.test.ts`)
- A missing file yields a clean v2 initial state.
- Invalid JSON throws the fix-it-yourself error; unsupported schema throws.
- A v1 file migrates to v2 (synthetic session, re-keyed rows, dangling-feedback repair).
- Concurrent updates serialize correctly and leave no stale lock.
- Integrity violations are rejected.

### Adapter (`mapper.test.ts`, `actions.test.ts`)
- The mapper narrows multi-session state to a single scoped session and round-trips field names.
- Bridge actions validate payloads (`BridgeApiError` on bad input) and drive the full council flow.
- Multi-session switching keeps per-session feedback isolated.
- The state watcher fires on file change (live-update path).

### Consensus (`modelCouncil.test.ts`)
- Proposal prompts inject the objective-consensus directive and ask for an independent answer.
- Deliberation prompts require a `CANDIDATE_CONSENSUS:` section and instruct peers to adopt stronger reasoning.
- Ratification prompts require a leading `CONSENSUS: ACCEPT|BLOCK` marker and frame each member as a peer, not a chair.

## What Is *Not* Unit-Tested

| Area | Why / how it's covered instead |
|------|-------------------------------|
| Live summon (Claude/Codex) | Requires authenticated CLIs; exercised manually + via `summon-debug.log` |
| Live Model Council network calls | Requires `OPENROUTER_API_KEY`/Codex auth; only the prompt protocol is unit-tested |
| Electrobun desktop runtime | Validated by the CI build-smoke job (artifact generation), not unit tests |
| CLI binary | Validated by CI smoke (`--version`, `--help`) |
| React UI | No component tests; behavior covered through the shared `actions` layer |

## Testing Philosophy

The suite targets the **deterministic core** — domain logic, persistence/migration, mapping, and prompt construction — where bugs are silent and costly. Anything requiring live external agents/models is verified through integration smoke (CI) and manual runs rather than mocked unit tests, keeping the suite fast and free of brittle network mocks.

## Adding a Test

1. Co-locate `<module>.test.ts` next to the code.
2. For anything touching state, use an isolated temp state path and clean up in `afterEach`.
3. Prefer asserting on observable results (returned state, persisted file) over internals.
4. For prompt/protocol logic, test the pure builders, not the network call.
5. Run `bun test` plus `bun run typecheck` and `bun run lint` before committing.
