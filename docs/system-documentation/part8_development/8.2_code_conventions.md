The codebase follows a small, consistent set of conventions enforced by Biome and TypeScript, plus the project's stated "simplicity-first" implementation rules from `CLAUDE.md`/`AGENTS.md`.

## Formatting & Linting (Biome)

`biome.json` is the single authority:

| Rule | Value |
|------|-------|
| Indentation | 2 spaces |
| Line width | 120 |
| Lint rules | Biome `recommended` |
| Import organization | off (manual ordering) |
| Ignored | `dist/`, `Design Council Hall Interface/` |

```bash
bun run lint          # biome lint .
bun run format        # biome format --write .
bun run format:check  # check formatting only
```

## TypeScript

- **Strict typing throughout.** Type checking is a CI gate (`tsc --noEmit`).
- **Domain ⇄ wire separation.** camelCase domain types (`core/services/council/types.ts`) are kept structurally distinct from snake_case wire DTOs (`interfaces/mcp/dtos/types.ts`, `interfaces/chat/ui/types.ts`) and bridged only through explicit mappers.
- **Discriminated literals over enums.** Statuses use string literal unions (`"active" | "closed"`, `"open" | "closed"`) rather than TS enums.
- **`unknown` at the edges.** Bridge actions accept `unknown` payloads and narrow them with explicit `requireString`/`optionalString` guards; the store accepts `unknown` JSON and normalizes it.

## Architectural Conventions

| Convention | Example |
|-----------|---------|
| Inward-only dependencies | `core` imports nothing from `interfaces`/`cli` |
| Pure updaters under lock | every mutation is `store.update(state => ({state, result}))` |
| Result-carrying mutations | service results include the full `state` snapshot |
| Defensive normalization | every state read is normalized + integrity-checked |
| Errors as values at boundaries | throw internally; convert to `CallToolResult`/`BridgeResult`/HTTP at the edge |
| Field-name tolerance | normalizers accept camelCase **or** snake_case for forward/backward compatibility |

## Simplicity-First Rules

From the project's own `CLAUDE.md`/`AGENTS.md`, paraphrased:

- **Prefer one implementation** for similar concerns; refactor to a shared helper instead of duplicating (e.g. the bridge `actions` reused by HTTP and RPC; the `mapper` reused by MCP and bridge).
- **Keep APIs minimal.** Favor *load + upsert* over load/save/update; do not add unused methods (e.g. `summonSettings` exposes only `loadSummonSettings`/`upsertSummonSettings`).
- **Avoid extra layers** (services, normalizers, versioning) unless there is an immediate, proven need.
- **Keep behavior consistent across similar stores** (defaults, parse errors, locking) — `state.json` and `config.json` share the `fileStore` primitives.
- **Don't add exported helpers just to compute a path**; derive from existing paths or add one shared helper (e.g. `config.json` is derived as a sibling of the resolved state path).

## Naming

| Kind | Convention | Example |
|------|-----------|---------|
| Domain types | PascalCase, `Council*` prefix | `CouncilSession`, `CouncilFeedback` |
| Wire DTOs | PascalCase, `*Dto` / `*Params` / `*Response` | `SessionDto`, `StartCouncilParams` |
| Functions | camelCase verbs | `startCouncil`, `resolveAgentName`, `mapCouncilState` |
| Constants | UPPER_SNAKE | `LOCK_STALE_MS`, `SUPPORTED_SUMMON_AGENTS`, `DEFAULT_MAX_CONSENSUS_ROUNDS` |
| Files | camelCase | `fileStateStore.ts`, `summonSettings.ts` |
| Tests | `<name>.test.ts` co-located | `index.test.ts`, `mapper.test.ts` |

## Error Messages

Errors are written for the human who will read them, with the fix embedded where possible:

```text
"State file is invalid JSON at <path>. Fix or remove the file and retry."
"get_current_session_data needs a stored agent name. Call join_council (or start_council) once, then retry."
"Port <n> is already in use. Close the other council chat instance or launch with --port/-p to use a different port."
```

## Comments

Comments are sparse and explain *why*, not *what* — e.g. why a stderr banner is used (to avoid polluting the stdio MCP protocol), why a `query.interrupt()` is fire-and-forget (it may hang), or why the watcher swallows errors (to avoid destabilizing the server). Match this density when contributing.

## Asynchronous Patterns

- `async`/`await` throughout; no callback chains.
- Parallel fan-out via `Promise.all` (Model Council members per round).
- External probes always wrapped in `withTimeout(..., 8000)` and subprocesses killed in `finally`.
- Background refreshes are deliberately fire-and-forget (`void promise.catch(() => {})`).
