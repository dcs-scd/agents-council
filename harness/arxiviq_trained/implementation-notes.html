Implementation Notes — arxiviq-trained (corpus-fitted autonomous review skill)

2026-06-19 DECISION

HALO-X runs in the primary tree, not a worktree. The build target (agents-council/harness/, incl. the 399-review corpus and all arxiviq_trained/ artifacts) is entirely gitignored by the root /* blanket rule — 0 tracked files. A HALO-X git worktree contains only committed files, so it would be empty of the corpus. Using the sanctioned single-run-in-primary-tree exception (.halo-x/ALLOW_PRIMARY).

Why: worktree isolation guards against parallel runs colliding on a shared tree; there is no such collision risk on a gitignored target with no other active arxiviq_* run. The documented gitignored-tree landmine (empty worktree) makes the exception the correct, not lazy, choice.

2026-06-19 DECISION

"Autonomous" (option ii) = in-session Opus 4.8 generation with the critic loop replacing the human eye; held-out eval defaults to in-session over ~12 papers. Reconciles "use you to generate" with "no human in the loop": the pipeline runs ingest→retrieve→draft→critic→render without stopping to ask the user, and the critic + gate stand in for the reviewer. No Anthropic API key or batch spend required. A batch-20 API blind eval (claude-opus-4-8) is a flagged upgrade, explicitly out of scope now.

Why: a true headless API service would be a bigger build and needs a key + budget the user hasn't provisioned; the in-session reading delivers the same autonomous product for the user's stated usage and unblocks immediately.

2026-06-19 DECISION

"Trained skill" = corpus-fitted prompt program, not weight training. Opus 4.8 is not fine-tunable by the user. The trainable surface is the skill's data: a mined style-card (measured thresholds), a retrieval index of the 392 paired reviews injected as few-shot exemplars, and a critic rubric. These are fit to the 399 and validated against held-out members of it (eval-driven prompt-program optimization).

Why: sets the right expectation — the deliverable is portable data loaded into a stateless engine at run time, which is exactly the user's usage model ("give you a paper + the trained skill").

2026-06-19 FYI

The current skill is provably un-fitted — evidence that motivated the build. Measured corpus visible-word distribution: median 1,439 (p25 1,323, p75 1,574). The skill's own spec says 2,000–3,000 words, floor 1,500 — ~40% over the real median, and visible-word counts overcount prose so the true gap is larger. The single most measurable parameter is mis-set because voice.md was hand-estimated. WU-MINE replaces it with mined numbers.

Why: documents the concrete defect the build fixes, and the length-IQR invariant (≈1,320–1,575) that supersedes the legacy target.
